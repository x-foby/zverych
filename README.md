# Community bot

Telegram-бот — участник группового чата. ТЗ и принятые решения: [SPEC.md](SPEC.md).

## Быстрый старт

1. **Создайте бота** в [@BotFather](https://t.me/BotFather): `/newbot`, затем `/setprivacy` → выберите бота → **Disable**.
2. **Токены:** `cp .env.example .env`, впишите `TELEGRAM_BOT_TOKEN` и `OPENROUTER_API_KEY`
   (ключ — на [openrouter.ai/keys](https://openrouter.ai/keys), нужен пополненный баланс). Модель по
   умолчанию — Gemma 4 26B-A4B через OpenRouter (см. SPEC.md, раздел 7).
   Расходы ограничьте лимитом на ключе в OpenRouter (с ежедневным сбросом): когда он исчерпан,
   бот молчит до 00:00 UTC. Переписка не отправляется хостерам, которые хранят данные запросов
   (`provider: {data_collection: deny}` в `config.yaml`).
3. **Конфиг:** `cp config.example.yaml config.yaml`, впишите свой Telegram ID в `telegram.admin_ids` (узнать — написать [@userinfobot](https://t.me/userinfobot)). Персона: `cp persona.example.md persona.md` и опишите характер бота (`persona.md`, как и `config.yaml`, локальный и не попадает в git). Это персона по умолчанию: админ группы может задать своей группе другую — словами в группе («Зверыч, теперь ты фанат джаза») или в личке, с подтверждением кнопкой в личке.
4. **Добавьте бота в группу** (может кто угодно) и сделайте его администратором группы с минимальными правами — иначе Telegram не присылает ему реакции участников. Если он был в группе до отключения privacy mode — удалите и добавьте снова. В новой группе бот **выключен**: молчит, ничего не хранит и не тратит токены.
5. **Включите группу** в личке с ботом (вы — создатель, `telegram.admin_ids`): «включи бота в Звукарне, админ @vasya, режим тишина». Режимы — **тишина** (бот только читает и запоминает), **только реакции** и **общение**. Если бот ещё не знает @vasya, он подождёт, пока тот напишет в группе, и спросит вас кнопками «Да, это он» / «Нет»; после «Да» группа включается.

### Запуск локально

```sh
go run ./cmd/bot
```

### Запуск на сервере (Docker)

```sh
docker compose up -d --build
docker compose logs -f
```

### Локальная модель вместо OpenRouter (необязательно)

Скачайте в `./models` официальную квантизацию Gemma 4 от Google
([google/gemma-4-26B-A4B-it-qat-q4_0-gguf](https://huggingface.co/google/gemma-4-26B-A4B-it-qat-q4_0-gguf),
~15.6 ГБ; нужно 24–32 ГБ RAM) и раскомментируйте провайдера `local` в `config.yaml`:

```sh
./scripts/get-model.sh
llama-server --model models/gemma-4-26B_q4_0-it.gguf --mmproj models/gemma-4-26B-it-mmproj.gguf \
  --port 8080 --ctx-size 8192 --jinja        # без Docker; base_url: http://localhost:8080/v1
docker compose --profile local up -d --build  # в Docker; base_url: http://llm:8080/v1
```

## Создатель, админы и авторитеты

**Создатель** бота (`telegram.admin_ids`) управляет группами из лички с ботом: «какие у тебя группы?»,
включить группу (админ и режим, см. «Быстрый старт»), назначить и снять админа («@anya тоже админ в Звукарне»,
«@vasya больше не админ»), отключить группу («отключи бота в Звукарне» — после подтверждения кнопкой бот стирает
всё, что знал о группе, и молчит в ней). Больше создатель боту ничего не указывает и памяти групп не видит:
чтобы учить бота, назначьте админом себя. Во включённой группе назначить админа можно и фразой там:
«@vasya тут админ», ответом на его сообщение, себя — «Зверыч, я тут админ».

**Админов** в группе может быть несколько — это не администраторы группы в Telegram. Новых админов назначают
создатель и любой админ; снять другого админа может только создатель, админ может снять себя; последнего
админа снять нельзя — только отключить группу. Указания бот принимает, только когда к нему обращаются лично
(«Зверыч, запомни…»); разговор о нём в третьем лице («Зверыч должен это запомнить») — не указание.

Всё это админ может и **в личке с ботом** — там же можно просто поговорить: бот помнит группу, но переписка
из лички в группу и в её память не попадает. Если у админа несколько групп, он называет нужную («в Звукарне…»),
бот запоминает выбор. Авторитетов и остальных участников бот в личке не слушает и не отвечает им. Админ может:

- менять режим — «Зверыч, помолчи», «молчи, но реакции ставь», «можешь говорить»; в тишине бот указания
  выполняет молча, в режиме реакций подтверждает их 🫡, на обращения не отвечает (ответы — в личке);
- назначать и снимать авторитетов — «@petya тоже можно слушать»;
- просить запомнить — «Зверыч, запомни: Вася основал этот чат»; «…в этом топике» — запись только для топика;
- задавать правила — «в этой ветке не пиши», «новичкам советуй прочитать закреп», «ставь ❤️ на мои
  сообщения», «на любое упоминание Андрея Степанова отвечай «С Днём рождения!»». Правила про сообщения
  выполняет модель при оценке новых сообщений (раз в `batch_interval_seconds`, по умолчанию раз в час;
  если пишет собеседник бота — без имени и reply, но в разговоре с ним, — через `dialog_wait_seconds` его
  тишины, лог `dialog: evaluating now`; новое сообщение от него отменяет оценку, пока бот не начал отвечать):
  реакции и ответы по правилу — и в cooldown; фразу в кавычках бот отправляет дословно; одному автору
  ответ по одному правилу — не чаще раза в сутки;
- отменять — «забудь про закреп»; спросить «что ты помнишь?» — бот пришлёт список (и сводку старой переписки топика);
- стирать сводку старой переписки топика — «Зверыч, забудь, о чём тут говорили раньше»;
- стирать тон топика, который бот заметил сам, — «Зверыч, забудь, как тут принято общаться» (задать тон — указанием: «Зверыч, в этом топике говори без мата»);
- смотреть, что бот думает о человеке, — «Зверыч, что ты думаешь о @vasya?», стирать — «Зверыч, забудь, что ты думаешь о @vasya»;
- давать указания для другого топика по названию — «Зверыч, в Барахолке не пиши» (в группе или в личке). Названия топиков бот
  узнаёт из апдейтов Telegram — при создании и переименовании топика и с первым сообщением в нём без reply (лог `topic name`);
  топик, названия которого бот ещё не знает, он назвать не может — тогда указание дают в самом топике.

Старую переписку бот помнит по **сводке** (SPEC 4.5): когда в топике набирается `summary_chunk_messages` (40)
сообщений старше последних `context_messages`, модель фильтра фоном дописывает их в сводку топика (до
`summary_max_chars`, 1500 символов). Сводка идёт в ответы и в оценку и не удаляется по `retention_days`; сообщения,
которые вот-вот удалятся, сворачиваются заранее. В логе: `summary updated chat_id=… topic=… messages=40 chars=…`.

С той же порцией бот обновляет **заметки об участниках** (SPEC 4.5): как к человеку относится чат (с репутацией
−2…+2) и своё впечатление о нём — до `note_max_chars` (300) символов каждая часть. Заметки идут в ответы и в оценку,
репутация видна модели пометками «[уважают]», «[не в чести]» в переписке; прав она не даёт. В логе: `notes updated … written=…`.

Ещё одним запросом по той же порции бот сам выделяет **лор** (SPEC 4.5): местные шутки, правила и договорённости,
традиции, термины — для топика или всего чата. Свою запись, которую переписка уточнила, он переписывает, записи
руководства не трогает; своих записей — не больше `lore_max_entries` (30) по `lore_max_chars` (200) символов. Они видны
в «что ты помнишь?» с пометкой «(сам заметил)», забыть их может админ и авторитет. В логе: `lore updated … added=… replaced=…`.

И последним запросом по порции бот уточняет **тон топика** (SPEC 4.6): как здесь принято общаться — мат и стёб или
вежливо и по делу, на «ты» или «вы». Описание (до 250 символов) идёт в «Местные обычаи» только этого топика; нижняя
граница (без травли, оскорблений по признакам и угроз) действует везде. В логе: `tone updated … tone=…`.

Авторитеты тоже могут просить запомнить и задавать правила (отменять — свои и те, что бот заметил сам), но никого не назначают.
Выполненное указание бот подтверждает реакцией 🫡; просьбы обычных участников он как команды не выполняет.
В логе: `command … command=set_lead done=true`.

## Как понять, что происходит

`log_level: debug` в `config.yaml` показывает пропуски по cooldown/квоте и работу LLM. На уровне `info` видны
оценка пачки и каждое действие (`rule` — номер указания, по которому оно сделано):

```
evaluation chat_id=-100… messages=12 actions=2
evaluation reaction chat_id=-100… message_id=345 emoji=❤ rule=8 reason="сообщение Ани"
evaluation reply chat_id=-100… target=350 rule=0 reason="вопрос ко всем про компрессор"
```

По этим `reason` удобно подстраивать `persona.md`.

## Тесты

```sh
go test -race ./...
```

Разбор указаний на живой модели (без `LIVE_LLM_URL` тест пропускается). Прогоняйте после правок
`commandPrompt` и `privateCommandPrompt` (`TestLiveCommandParsing`, `TestLivePrivateParsing`) и при смене модели. Через OpenRouter (в конце теста — стоимость прогона):

```sh
set -a; . ./.env; set +a     # ключ из .env в окружение
LIVE_LLM_URL=https://openrouter.ai/api/v1 LIVE_LLM_KEY=$OPENROUTER_API_KEY \
  LIVE_LLM_MODEL=google/gemma-4-26b-a4b-it go test ./internal/brain -run TestLive -v
```

На локальном `llama-server`: `LIVE_LLM_URL=http://localhost:8080/v1 go test ./internal/brain -run TestLive -v`.

С `LIVE_LLM_MODEL` оценка и разбор указаний идут с JSON-схемой ответа, как у бота с `structured_outputs: true`;
`LIVE_LLM_SCHEMA=0` — без схемы (как у модели без structured outputs).

Мутационное тестирование: go-mutesting только генерирует мутантов, а `scripts/mutation`
прогоняет их параллельно через `go test -overlay` (рабочая копия не меняется; отчёты в `.mutation/`):

```sh
go install github.com/avito-tech/go-mutesting/cmd/go-mutesting@latest  # Go ≥ 1.27; для 1.25–1.26: @466f39c
scripts/mutation.sh                       # все пакеты
scripts/mutation.sh ./internal/brain      # выбранные
scripts/mutation.sh -min-msi 0.85         # код выхода 1, если счёт ниже порога
scripts/mutation.sh -h                    # остальные флаги (-j, -timeout, -blacklist, -keep)
```

## Фото

Бот видит фото, если отвечает на него или на сообщение с непосредственным reply на фото. Можно прислать фото с подписью «Зверыч, что здесь?» или спросить reply-ем. В личке админа работают фото и reply на фото. Нужна модель ответа с поддержкой изображений. Фото загружаются только для ответа, до 10 МиБ; на диск не сохраняются. Видео, стикеры и картинки, присланные как файл, пока остаются текстовыми пометками. Альбомы не объединяются.

Если лор нужных топиков превышает 6000 символов, модель фильтра отбирает факты по смыслу текущего разговора (`lore_select`, `lore selected by meaning`). Указания включаются всегда; факты руководства приоритетнее наблюдений бота. При ошибке используется прежний отбор по новизне. Если записи помещаются, дополнительного запроса нет.
